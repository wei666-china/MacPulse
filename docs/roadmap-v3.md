# MacPulse v3 施工蓝图(待 Wei 审批)

2026-08-12 · 起草:Claude · 状态:**等审批,未开工**

## 一句话定位

> 不做「更全的 iStat」,做「会看病的性能 App」——每个数字都能点开问一句为什么。

「全」补到及格线(入场券),「诊断」做到没有对手(卖点)。已上线的充电链路
面板就是这个定位的第一个样板:不止显示 96W,还告诉你瓶颈在哪一环。

## 竞品格局(2026-08 调研)

- **iStat Menus 7**($11.99):商业天花板。全传感器图表、每核 CPU、分 App 网络/磁盘。
- **Stats**(免费,MIT,41k star):开源天花板。九大模块 + 菜单栏 widget 自由组合。
- **MoniThor / Pulse**:MAS 新生代,轻量好看。
- 单点专精:TG Pro(风扇)、AlDente(充电上限)、Sensei(盘健康)。

结论:堆模块正面刚必输;全类目没人做「诊断」,这是唯一空位。

## 全程铁律(每一期都适用)

1. **不编数据**:读不到显示「不可用」,机型不支持写「本机型不提供」,绝不显示 0。
2. **真值对账**:每个新读数都配独立工具对拍测试(ioreg/pmset/vm_stat/smartctl…),
   不许自己对自己。
3. **先备份再动工**:tag + bundle 进 `~/Documents/macpulse-backups/`,新分支开工。
4. **借码只借 MIT**:逐目录核实许可证边界(WhatCable 的流程),署名进
   THIRD_PARTY_NOTICES.md。
5. 代码按「将来能公开发布」的标准写;开发者账号($99/年)等真要发布那天再办。

## 第一期:基建还债——请走 mactop(推荐先行)

**为什么先做这个**:功耗/温度现在靠捆一个 Go 写的 mactop,有实测内存泄漏
(2 秒档连跑 20 小时,36MB 涨到 1.07GB)。所有「做大」的计划压在这条裂缝上。
Stats(MIT)有成熟的原生 Swift SMC/传感器实现,可合法改编——与充电链路
引 WhatCable 同一套打法,今天刚验证过全流程。

**交付物**
- 原生 Swift 读取:SMC 温度/风扇/功耗轨,IOReport 能耗模型(CPU/GPU/ANE 频率与占用)
- 删除 mactop 二进制与 Go 工具链依赖,App 体积与内存占用显著下降
- 顺手解锁两个新数据源:**风扇转速**、**全机温度传感器清单**(第二期直接用)
- 采集器进程(MacPulseCollector)职责收编或简化

**验收标准(你亲眼验)**
- 活动监视器里 MacPulse 全家桶连跑 24 小时,内存曲线平的
- 总览页所有现有数字照常显示,和升级前对拍误差在正常波动内
- 145+ 测试全绿,新增读数每个都有独立真值对账测试

**风险**:SMC 键位随机型变化 → 用 Stats 经过 41k star 用户验证的键位表;
读不到的键按铁律显示不可用,不猜。

**量级**:大。一次大手术,预计占一整个工作段(多个会话)。

## 第二期:类目补齐到及格线,每个都带「解释」

**交付物**(每项 = 数据层 + 面板 + 至少一条诊断)
- **GPU 面板**:占用/频率/显存压力;诊断「谁在吃 GPU」(进程归因)
- **磁盘面板**:容量构成(谁占的)、实时读写、SMART 健康;诊断「空间去哪了」
  「写入量是否异常」
- **传感器/风扇面板**:全机温度地图 + 风扇曲线;诊断「热从哪来:是 CPU 还是
  充电还是环境」(接第一期数据)
- **蓝牙外设电量**:鼠标/键盘/耳机电量进总览与通知
- 每个新面板的空态、错误态、机型不支持态都写文案,不留白屏

**验收标准**:六主标签变八(或分组重排,见第三期);每个新数字都能答一句
「为什么」;对账测试覆盖。

**量级**:大。可拆成 2a(GPU+磁盘)/ 2b(传感器风扇+蓝牙)两次审批。

## 第三期:苹果化外壳

**交付物**
- 手搓的玻璃卡片(LiquidCard)换成 macOS 26 官方 Liquid Glass 材质 API,
  跟随系统强调色、明暗、透明度减弱等辅助设置
- 总览页信息架构重排:一屏答完「机器现在怎么样」,细节下钻
- **菜单栏 widget 体系**:像 Stats 那样自由组合(只放电量/只放温度/组合条),
  拖拽排序
- **桌面小组件**(WidgetKit):电量+功耗+温度的桌面常驻卡
- 通知中心:阈值可配(温度过线、电池健康掉档、磁盘将满、外设没电)

**验收标准**:与系统设置 App 并排截图不违和;你的「反 AI 感」一票否决权。

**量级**:中偏大。设计细节多但风险低,适合放在数据层稳定之后。
